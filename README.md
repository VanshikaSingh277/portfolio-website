# 🌐 Vanshika Singh Chauhan - Portfolio

A modern and responsive personal portfolio website showcasing my skills, projects, experience, achievements, and coding journey.

**Live:** [vanshikasingh.vercel.app](https://vanshikasingh.vercel.app/)

## Project structure

```
frontend/              Static site (deployed to Vercel)
  index.html           The page; editable regions are wrapped in <!--@name-->…<!--/@name-->
  css/ js/ assets/     Styles, scripts (js/config.js sets the API URL), images
  resume/              Resume PDF(s)
  robots.txt           ┐
  sitemap.xml          ├ generated by `npm run export` — don't edit by hand
  llms.txt             ┘
backend/               Node.js + Express API (deployed to Render)
  content/             ✏️ All editable content: profile, projects, experience, skills (JSON)
  src/server.js        API + local admin panel
  src/export.js        Renders content/*.json into frontend/
  admin/               Local admin panel UI (http://localhost:5000/admin)
```

## Setup

Requires Node.js 20+.

```bash
cd backend
npm install
cp .env.example .env      # then fill in the values
```

| Command | What it does |
| --- | --- |
| `npm start` | Run the API on `http://localhost:5000` |
| `npm run dev` | Same, restarting on file changes |
| `npm run admin` | Run the API **and** the admin panel (needs `ADMIN_PASSWORD` in `.env`) |
| `npm run export` | Write `content/*.json` into `frontend/index.html`, `robots.txt`, `sitemap.xml`, `llms.txt` |
| `npm run export:check` | Exit with an error if `frontend/` is out of date with the content |

To view the static site locally, open `frontend/index.html` with any static server (e.g. VS Code Live Server on port 5500), or use the admin preview at `http://localhost:5000/site/`.

## Updating the portfolio: edit → export → push

1. `cd backend && npm run admin`, open **http://localhost:5000/admin** and log in with your `ADMIN_PASSWORD`.
2. Edit **Profile**, **Projects**, **Experience**, **Tools and skills**, or upload a new PDF under **Resume**.
3. Click **Save changes** (or Ctrl+S). A snapshot is taken first, so **History** can restore any earlier version.
4. Click **Export to site** (same as `npm run export`). Check the result at **http://localhost:5000/site/**.
5. Commit and push. Vercel redeploys the site automatically:
   ```bash
   git add backend/content frontend
   git commit -m "Update portfolio content"
   git push
   ```

You can also edit the JSON files in `backend/content/` directly and run `npm run export`.
Only the marked regions of `index.html` are rewritten; everything else (layout, nav, contact section, footer) is edited in the HTML as usual.
Running the export with unchanged content changes nothing.

## SEO, GEO, AEO and LLMO

Everything below is generated by `npm run export` from `backend/content/*.json`, so it stays in sync with the page. Edit it in the admin panel under **Site & SEO**.

- **SEO**: title, meta description, canonical URL, robots, author, theme-color, Open Graph tags (image size read from the file), and Twitter cards. Also `sitemap.xml`, whose `lastmod` is the date of the last export that actually changed the site.
- **AEO**: a visible FAQ section above Contact and FAQPage structured data built from the same questions. The About section starts with a one-sentence answer to "Who is Vanshika Singh Chauhan?".
- **GEO**: one JSON-LD `@graph` containing `Person`, `WebSite`, `ProfilePage` and an `ItemList` of projects (`SoftwareSourceCode` when there's a repository), plus the `FAQPage`.
- **LLMO**: `llms.txt` (see [llmstxt.org](https://llmstxt.org)): the whole portfolio as Markdown in one file. Also a `robots.txt` that allows GPTBot, ClaudeBot, PerplexityBot, Google-Extended and other AI crawlers.
- **Analytics**: GA4 using `gaId` from `profile.json`, loaded by `frontend/js/analytics.js`. It never loads on localhost and is off when `gaId` is empty. Custom events: `resume_download`, `contact_submit` (successful sends only), `project_link_click`, `social_click` and `outbound_click`.
- **Performance**: fonts load without blocking the first paint, all scripts are deferred, and the hero photo has explicit dimensions and high fetch priority. `frontend/vercel.json` sets clean URLs, content types and long caching for `/assets`.

```bash
npm run export      # regenerate everything
npm run seo:check   # validate it: meta tags, JSON-LD, FAQ, headings, images, crawl files (exits 1 on failure)
```

`/assets` files are cached for a year. To change an image, give it a **new file name** rather than overwriting it.

After deploying, submit `https://vanshikasingh.vercel.app/sitemap.xml` in [Google Search Console](https://search.google.com/search-console) and test the page with the [Rich Results Test](https://search.google.com/test/rich-results).

## API

| Method | Path | Description |
| --- | --- | --- |
| GET | `/api/health` | Health check |
| POST | `/api/contact` | `{ name, email, message, website }` → sends an email. `website` is a honeypot and must be empty. Limited to 5 requests per 15 minutes per IP. |
| GET | `/api/projects` | All projects from `content/projects.json` |
| GET | `/api/projects/:id` | One project, or 404 |

Browsers may only call the API from origins listed in `ALLOWED_ORIGINS`.
In development, if `SMTP_HOST` is empty, contact messages are printed to the console instead of being emailed.

## Deployment

### Frontend: Vercel
- Import the repo in Vercel and set **Root Directory** to `frontend`. No build command is needed.
- After the backend is live, replace the placeholder in `frontend/js/config.js` (`https://YOUR-RENDER-SERVICE.onrender.com`) with your Render URL, then push.

### Backend: Render
- New **Web Service** → root directory `backend`, build command `npm install`, start command `npm start`.
- Environment variables: `NODE_ENV=production`, `ALLOWED_ORIGINS=https://vanshikasingh.vercel.app`, `TRUST_PROXY=1`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `CONTACT_TO`.
- **Do not set `ADMIN_PASSWORD` on Render.** The admin panel only runs locally: it needs `npm run admin` (the `--admin` flag), an `ADMIN_PASSWORD`, and a non-production `NODE_ENV`, and it only listens on `127.0.0.1`. `npm start` never enables it. Content changes reach the live site through git, not through the server.
- Render free instances sleep when idle, so the first contact-form request after a while can take ~30 seconds.
